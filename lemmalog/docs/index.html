An agent's memory should be a deductive database.

Vector stores retrieve; they don't reason. When an agent needs to know who Alice reports to now, whether two names are the same entity, or what changed since last turn, re-reasoning it in-context is slow, expensive, and non-deterministic.

Lemmalog moves that work out of the model. Base facts are asserted once at the extraction boundary; rules derive temporal projections, closures, canonicalizations, and aggregates. Every derived fact carries a proof tree back to its source episodes, and each turn updates derived views incrementally instead of recomputing them — or worse, re-prompting for them.

The engine

What a memory actually needs

Δ

Incremental by construction

Seminaive evaluation with per-epoch deltas: a turn only derives what new facts imply. Retraction is a scoped negative delta that rebuilds only transitive dependents.

~50 ms incremental turn vs ~17 s cold fixpoint; idle turns cost µs.

⊢

Provenance, not vibes

Confidence and provenance annotations on every fact. why() returns a proof tree from any conclusion down to the verbatim episodes that support it.

Merge on re-derivation: max conf, union provenance.

≔

Deterministic updates

A Mem0-style policy decides ADD / UPDATE / NOOP without a model call. Exclusive predicates supersede by closing the old bi-temporal interval; real conflicts escalate instead of silently merging.

Updates, temporal projection, abstention: rule-derived, exact.

?

Demand queries

ask_deep() answers point queries via magic-sets rewriting — only the demand-relevant slice is derived, the base store untouched.

Point lookups in ~100 µs at 4M facts.

~

Hypotheticals

what_if() assumes temporary facts, runs to fixpoint, answers a goal, and restores the store byte-identically — lookahead without commitment.

Relations, change log, epoch: all restored.

≡

Entity resolution

The LLM proposes alias edges; Datalog derives the closure and projects canonical views read-side only. Topology violations become alias_conflict facts, never silent merges.

Confidence propagates: weak merges look weak.

The rule language

Small enough to write by hand, or by model

Runtime-parsed, stratified Datalog with negation-as-absence, bi-temporal columns, arithmetic in comparisons, and aggregation in rule heads. Rules install as versioned batches an agent can revert; installing mid-session backfills against existing facts.

rules.dl
# temporal projection: what's true now
current(E,R,O) :- edge(E,R,O,VF,VT,_),
                  now(T), VF =< T, T < VT.

# transitive closure
reports_to(X,Y) :- current(X,"manager",Y).
trans: reports_to(X,Z) :- reports_to(X,Y),
                           reports_to(Y,Z).

# stratified negation
orphan(E) :- entity(E), !current(E,_,_).

# aggregation in the head
kit_count(P, count(K)) :- bought(P, K).
big_spender(P) :- kit_count(P, N), N >= 3.

# bounded relevance diffusion
near(S,E,1) :- mentions(S,E).
diffuse: near(S,E2,D) :- near(S,E1,Dm),
             Dm < 3, D = Dm + 1, edge2(E1,E2).
Stratified, checked at install

Recursion through negation is rejected up front; aggregation dependencies stratify like negation edges, so folds complete before any reader evaluates.

Loud failures, built for self-correction

Unparseable goals and rejected batches return the offending input, the precise reason, and a corrected example. Silent zero-fact ingestion is impossible — every dropped line reports why.

Hybrid retrieval at the boundary

context_for_query ranks facts with BM25 + entity-graph boosting and assembles a budgeted context: distilled facts on top, verbatim provenance episodes at the bottom.

Streaming change feed

Every addition, retraction, and clear is epoch-stamped. Checkpoint once, and an external projection — a vector index, a UI, another agent — receives exactly the next turn's window.

Quickstart

Your agent's working memory, over MCP

The intended division of labor: the host model reads the conversation and asserts triples; Lemmalog derives closures, temporal views, and canonicalizations deterministically. Twelve tools over stdio JSON-RPC, for Claude Code, Kimi CLI, or any MCP host.

1

Build the server

shell
cargo build --release --features mcp
2

Register it

Set LEMMALOG_MCP_PATH to persist memory across sessions.

shell
claude mcp add lemmalog --env LEMMALOG_MCP_PATH=~/.lemmalog.snapshot -- \
  /path/to/lemmalog/target/release/lemmalog-mcp
3

Assert, derive, ask, prove

session
lemmalog_observe       {"facts": "Alice --works_at--> Acme\nAlice --manager--> Bob"}
lemmalog_install_rules {"rules": "reports_to(X,Y) :- current(X,\"manager\",Y)."}
lemmalog_query         {"goal": "reports_to(\"Alice\", Y)"}   → Y=Bob
lemmalog_why           {"fact": "reports_to(Alice, Bob)"}     → proof tree
lemmalog_what_if       {"facts": "Dana --manager--> Alice", "goal": "..."}

Correctness

Tested like an engine, because it is one

450 randomly generated stratified programs are checked against a brute-force fixpoint oracle over the ground domain — the classic validation technique for Datalog engines — plus incremental-vs-single-shot equivalence and a 2,000-case parser fuzz.

If the engine derives it, an independent oracle agrees with it — and the few times they disagreed during development, the engine was fixed and the case became a regression test.
